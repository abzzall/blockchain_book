# Implementation 2 — Local transactions and receipt evidence

## Outcome

Use Hardhat's local development chain to create one successful transfer and one
reverted transaction. Explain the transaction and receipt fields from the values
printed by the supplied script. No public testnet, faucet, browser wallet, or
external explorer is required.

## Safety and environment

- Network: Hardhat's in-process local chain. Nothing leaves your machine.
- Assets: local test ether, created by the development chain and worth nothing.
- The local accounts use public development keys. They are suitable only for
  local testing and must never receive assets on a public network.
- Do not create or commit a real `.env` file for this lab. If a later project
  needs secrets, commit only `.env.example` with placeholder names and keep
  `.env` ignored.

## Files and command-line verification

`scripts/local-transactions.ts` creates the transactions on a fresh local chain.
`src/summarize-receipt.mjs` computes the required fields from a transaction,
receipt, and block. The tests run the same process automatically.

```bash
npm --workspace @blockchain-handbook/lab-02 test
```

Run the complete local walkthrough and record the values it prints:

```bash
cd part-04-ethereum-transactions-networks-and-wallets/labs/lab-02-wallets-transactions-explorers
npm run walkthrough
```

## What to record

Write these into `RESULTS.md`. Every one is reproducible on a fresh local
chain.

| Item | Where it comes from |

## A transaction that fails

Chapter 11 makes the point that being included and succeeding are different
facts. The walkthrough deploys `RejectEther`, a contract whose `receive`
function reverts. Sending one wei to that contract creates a mined transaction
whose receipt status is `reverted`. Compare the fee charged on the failed
transaction with the fee on the successful transfer.

## What to explain

Answer in your own words, a short paragraph each. There are no screenshots;
these answers are the evidence that you understood what you saw.

1. The walkthrough prints a transaction object and a receipt object. Which
   fields belong to the signed transaction, and which fields exist only after
   execution?
2. Your failed transaction cost a fee and changed nothing. Explain why the fee
   is charged anyway, in terms of what the network actually did.
3. A block explorer is a user interface over node data. What fields would you
   check directly from a node to verify the same facts without trusting an
   explorer page?
4. Multiply `gasUsed` by `effectiveGasPrice`. Some of that was destroyed and
   some was paid. Explain which, and why the split exists.

## Troubleshooting

- If Hardhat reports that dependencies are missing, run `npm install` from the
  repository root.
- If TypeScript output or Hardhat caches appear, leave them uncommitted. The
  repository `.gitignore` excludes ordinary generated files.
- If the failed transfer does not show status `reverted`, confirm that the
  recipient is the deployed `RejectEther` address and that the transaction set
  an explicit gas limit.
